# llm-lookahead-guard 기획 (애자일, 스프린트 1)

> 목표는 수익이 아니라 **GitHub 스타와 포트폴리오**. 투자 조언·실제 매매·주문 기능은 넣지 않는다.

## ① 문제 정의

| 항목 | 내용 |
|---|---|
| 대상 | LLM에게 과거 날짜의 시장 상황을 주고 매매 판단을 시키는 백테스트를 돌리는 사람: 개인 퀀트·학생, LLM 금융 논문 저자, TradingAgents·AI Hedge Fund·LangChain 기반 에이전트 사용자 |
| 문제 인식 | 모델이 그 날짜 **이후**를 이미 학습했을 수 있어 성적이 부풀려진다(look-ahead / temporal contamination). 알고는 있지만 "내 로그 어디가 새는지"를 확인할 값싼 도구가 없다 |
| 원하는 것 | 로그 파일 하나를 넣으면 몇 초 안에 "어느 기록이, 왜, 얼마나 위험한지"를 알려주고 CI에서 막아주는 것. 키·비용 없이 |
| 관찰되는 현상 | Look-Ahead-Bench: 일반 모델은 학습 밖 구간에서 alpha가 크게 꺾임. DatedGPT: 결과 기간을 학습한 모델에 연 26.4bp/σ "lookahead premium". 공개 저장소에는 날짜·티커를 그대로 넣은 프롬프트, 결정일 이후 사건을 담은 뉴스 요약, "would later rally" 같은 사후 서술이 흔함 |
| 기대 효과 | 백테스트 결과를 발표·공유하기 전에 1차 누수 점검이 기본 절차가 됨. 사용자는 "이 성적은 모델 기준일 이후 구간에서만 믿을 수 있다"를 숫자로 말할 수 있음 |

## ② 검증 가능한 가설

- **H1 (채택):** "`pip install` + 로그 하나로 30초 안에 기록별 누수 리포트를 주는 CLI를 공개하면, **공개 후 4주 안에 GitHub 스타 100개**와 **외부인 이슈·PR 3건 이상**(특히 모델 기준일 표 기여)이 생긴다. GitHub Insights(스타·트래픽)와 이슈 목록으로 확인한다."
- **H2 (품질):** "사람이 라벨링한 프롬프트 100개(누수 50/정상 50)에서 error 등급 규칙의 **정밀도 ≥ 0.8, 재현율 ≥ 0.6**. 스프린트 2에 라벨셋을 만들어 확인한다."
- **H3 (쓸모):** "공개 LLM 트레이딩 저장소 5곳의 예제 로그·프롬프트에 돌리면 **3곳 이상에서 LAG1xx/LAG3xx 실제 사례**가 나온다. 각 저장소에 정중한 이슈로 보고해(사람이 직접) 확인한다."

## ③ MVP 범위와 백로그

**MVP (스프린트 1, 이번에 완료)**
- 오프라인·무의존 파이썬 패키지 + `lookahead-guard` CLI (`check`, `mask`, `cutoffs`, `rules`, `demo`)
- 규칙 14개: 노출(LAG0xx), 프롬프트 미래 정보(LAG1xx), 식별자 노출(LAG2xx), 응답 회상(LAG3xx)
- 모델 기준일 표(OpenAI·Anthropic·Google·Meta 28개 항목, 사용자 JSON 덮어쓰기)
- 마스킹(날짜→`D-5`/`M-1`/`Q+1`/`Y-2`, 자산→`ASSET_n`, 사건→`EVENT_n`)과 되돌리기
- 마스킹 vs 원본 A/B 하네스(임의 callable, 네트워크 없음) + 가짜 암기 모델 데모
- 출력: text / json / GitHub Actions 주석, `--fail-on`으로 CI 차단
- 가상 예제 데이터, 테스트 77개, CI(3.9~3.13)

**백로그 (가치 대비 노력 순)**
1. 라벨셋 100개 + 정밀도/재현율 리포트 (H2) — M
2. 엔티티 별칭 묶기(`ACMR=Acme Robotics`가 같은 `ASSET_n`) — S
3. pre-commit 훅 + 재사용 GitHub Action(`uses: dongjushin-ai/llm-lookahead-guard@v0`) — S
4. SARIF 출력(코드 스캐닝 탭 연동) — S
5. LangChain 콜백 / OpenAI·Anthropic 클라이언트 래퍼 가드(호출 전 검사, 옵션으로 차단) — M
6. 뉴스·공시 문서의 `published_at` 메타데이터 검사(본문이 아닌 첨부 데이터 시점) — M
7. 사건 사전 확장(섹터별·국가별, 기여 가이드) + 한국 시장(KRX 티커·한글 회사명) — M
8. 모델 출시일 기반 "최악의 경우" 상한(`--worst-case release`) — S
9. A/B 하네스에 실제 API 어댑터(키 있을 때만) + 비용 상한 — M
10. 숫자 지문 재식별 위험 점수(가격 경로가 유명 구간과 닮았는지) — L → 쪼개야 함
11. 웹 플레이그라운드(브라우저에서 프롬프트 붙여넣기) — M

## ④ 에픽 → 피처 → 유저 스토리

### 에픽 A. 로그 점검 (Lint)
- **피처 A1. 노출 판정**
  - A1-1 (S) **누가** 백테스터가 **무엇을** 기록마다 "모델 기준일이 결정일·결과 구간을 덮는지"를 **왜** 학습된 결과로 점수를 받는 기록을 골라내려고.
    - 인수 조건: gpt-4o + 2023-03-01 + 20일 → `full`; 2023-10-25 → `partial`; 2023-11-01 → `none`. 테스트 통과.
  - A1-2 (S) 모르는 모델이면 추측하지 않고 경고, `--cutoff`·`--cutoffs`로 지정 가능.
    - 인수 조건: `claude-sonnet-4-6`처럼 더 새 버전이 옛 기준일을 물려받지 않음(테스트).
- **피처 A2. 프롬프트 미래 정보**
  - A2-1 (M) 결정일 이후 날짜를 과거형으로 서술하면 error, 예정·전망이면 info, 불분명하면 warning.
    - 인수 조건: "closed at 305 on 2023-05-26"(as_of 2023-03-01) → LAG101; "scheduled for Oct 30" → LAG103; 달 이름 "May"를 조동사로 오인하지 않음.
  - A2-2 (S) 결정일 이후에 생긴 사건 이름(예: SVB 사태) → LAG104.
  - A2-3 (S) "would later", "in hindsight" 등 사후 서술 → LAG105.
- **피처 A3. 식별자 노출**
  - A3-1 (S) 날짜·티커·회사명·사건명이 보이면 노출 모델에선 warning, 비노출이면 info.
- **피처 A4. 응답 회상**
  - A4-1 (S) 모델 답에 결정일 이후 사실이 과거형으로 나오면 LAG301 error.

### 에픽 B. 고치기 (Mask)
- B1 (M) **누가** 백테스터가 **무엇을** 날짜·자산·사건을 일관된 별칭으로 바꾼 프롬프트를 **왜** 같은 실험을 마스킹해서 다시 돌리려고.
  - 인수 조건: 같은 로그 안에서 별칭 번호 고정, 회사명과 티커가 같은 별칭, `unmask`로 자산명 복원, 마스킹 결과는 LAG2xx 0건.

### 에픽 C. 효과 측정 (A/B)
- C1 (S) 원본 vs 마스킹 점수 차와 95% 구간.
  - 인수 조건: 가짜 암기 모델에서 gap > 0, 식별자를 안 보는 모델에서 gap = 0.
- C2 (M, 백로그) 실제 API 어댑터 — 키 있을 때만, 비용 상한.

### 에픽 D. 배포·채택
- D1 (S) README 영어+한국어, 30초 빠른 시작, 비교표, 한계.
- D2 (S) CI 매트릭스, 설치형 CLI 스모크 테스트.
- D3 (S, 사람이 직접) PyPI 배포 · 홍보 글.
